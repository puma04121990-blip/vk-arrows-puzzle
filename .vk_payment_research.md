# VK payment research notes

Date: 2026-08-16.

The official VK Bridge page for `VKWebAppShowOrderBox` at https://dev.vk.com/bridge/VKWebAppShowOrderBox was opened, but it currently returns a technical-maintenance page, so exact method details could not be extracted from that page during this audit.

The official VKCOM/vk-bridge repository at https://github.com/VKCOM/vk-bridge was opened and identifies VK Bridge as the package for integrating VK Mini Apps with official VK clients on iOS, Android, and Web. The project structure references the core API package.

Local implementation currently calls `vkBridge.send('VKWebAppShowOrderBox', { type: 'item', item: itemId })`, grants the item only after `data.success`, and uses a local test-mode grant outside VK. The production callback-server dependency is documented in `js/payments.js` but needs a concrete callback implementation and idempotency protection.

Additional source: https://pkg.go.dev/github.com/globalarray/vksdk/v3/payments (opened 2026-08-16). It documents that payment notifications are POSTed to the configured HTTP/HTTPS callback URL, signed with a secret, and must receive a successful/error response within 10 seconds or VK retries. It exposes GetItem and OrderStatusChange handlers, and test-mode notification types have a `_test` suffix; test order IDs can overlap with production IDs. The raw GitHub source URL attempted for callback.go returned 404 and was not used as evidence.
